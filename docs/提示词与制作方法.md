# 提示词与制作方法（还原「我用 Codex 搓了个能语音巡检的机房」）

> 这是本项目的"制作资料"，记录如何把一个抖音成品视频还原成可运行软件。
> 对应视频结尾的三段提示词 / 参考说明 / Skill 来源。

## 0. 制作流程（先拆片，再让 AI 动手）

1. **拿素材**：解析抖音分享链接得到原始 mp4（本文档所在项目已存 `ref/douyin_original.mp4`）。
2. **拆片抽帧**：`ffmpeg -i douyin_original.mp4 -vf fps=1 frames/f_%04d.png`，再用 `ffmpeg ... tile=7x3` 生成时间线缩略图，先看清视频分几段、每段演示什么。
3. **规格化**：逐帧看清每一页的布局/文案/数字，写成 `docs/REQUIREMENTS.md` 这样的"逐页规格 + 接口契约"。
   - 关键技巧：文字小的面板用裁剪放大的方式读，例如把右侧助手面板裁出来单独看，才能读到"进风温度过高，温度 31.8 度，功率 2.23 千瓦"这种原文案。
4. **定契约再并行**：把"外壳 / 3D 场景 / HUD 图表 / 语音助手"拆成互不重叠的文件与接口，明确每个模块的对外方法名，然后让多个 AI 分工同时写。
5. **自检闭环**：每个模块都用 headless Chrome 截图 + 收集控制台报错，AI 自己看自己的截图改到自己满意为止。这是本流程里最值钱的一步。

## 1. 三段提示词

### 提示词 A：把参考视频规格化成开发需求

```
你是产品/技术分析师。附件是抖音视频抽帧图（1fps）和一个成品软件录屏。
请逐帧分析，输出一份《逐页规格说明书》，要求：
1) 说明整体设计语言：分辨率、主色/辅色十六进制值、面板样式（描边、四角括号、装饰线）、字体；
2) 按页签逐页列出：页面名称、三栏布局里每一块面板的标题、英文小标签、每个数字与全部中文文案（照抄原文，不要改写）；
3) 还原信息架构：顶部标题栏/页签/底部状态栏各有哪些元素与按钮；
4) 指出视频里 AI 助手面板的完整对话文案与按钮名称；
5) 输出"必须实现的功能清单"和"数据字段清单"（机柜、设备、告警、工单、能耗）。
如果某处文字看不清，请明确标注"不确定"，不要编造。
```

### 提示词 B：三维机房 + 数据大屏

```
你是 Three.js 与数据可视化工程师。请用纯前端（Three.js + Canvas 2D 手绘图表）实现一个
"IDC 智能运维管理平台"3D 机房可视化运维系统，需求见随附《逐页规格说明书》，硬性要求：
1) 三维机房程序化建模，不引入任何外部模型/贴图/字体文件，必须离线可跑：
   6 排 × 7 台 = 42 个机柜、架空地板与格栅、冷通道、精密空调、UPS/配电柜、顶部桥架、
   机柜状态灯带（正常绿/告警红脉冲/离线灰）、温度热力着色、告警红色光柱与地面光圈；
2) 机柜门可开合，开门后能看到 1U~42U 的设备（按后端给的 uStart/uSize 排布）与风扇模组，
   点击机柜/设备要能高亮并联动右侧信息面板；
3) 相机系统：总览/通道/单柜/告警等预设视角 + 平滑飞行聚焦 + 鼠标轨道控制；
   另做一个约 5 秒的代码生成片头（黑场→逐排点亮→镜头飞入→标题动画），可点击跳过；
4) 数字人助手"小维"：低多边形程序化角色，能走到指定机柜前（有行走动画），说话时有波形/气泡；
5) 六大页面 HUD 覆盖在画布上：总览、机房监控、资产管理、能效管理、告警中心、运维工单，
   面板用深色玻璃质感 + 青色描边 + 四角括号，所有图表用 Canvas 2D 手绘（禁止图表库）；
6) 提供 window.IDC 命名空间与事件总线，模块之间只通过事件与方法调用通信；
7) 性能：重复对象用 InstancedMesh 或共享几何材质，1440×810 下流畅。
完成后请自行用 headless Chrome 截图自检，确保无控制台报错。
```

### 提示词 C：能语音巡检的助手「小维」

```
你是语音交互工程师。请为上面的 3D 机房系统实现语音巡检助手"小维"（纯前端、离线）：
1) 语音输入：Web Speech API（zh-CN，interimResults），识别不到或不支持时自动降级为文字输入；绝不抛异常；
2) 语音播报：speechSynthesis 中文播报，可在界面上开关；播报时 3D 助手进入"说话"状态；
3) 意图解析：本地规则引擎（关键词/正则打分，不调用任何在线大模型），至少支持：
   巡检某机柜（含"A 区 2 号柜"这类口语与容错）、当前告警、检查电力数据/PDU、返回整间机房、
   分析原因/怎么处理、生成工单派人处理、现场处理完成复核归档、打开某排机柜/看冷通道；
4) 动作编排：解析到意图后要驱动镜头飞行、助手行走、机柜开门、告警高亮、工单状态流转、对话面板更新，
   并给出一句"下一步：xxx →"的建议；语气参考成品视频：
   "A-02 号机柜，进风温度过高，温度 31.8 度，功率 2.23 千瓦。检查进风通道与冷通道送风，确认温度传感器读数。"；
5) 未识别时回复："没听清，可以说『巡检 A-02』或『当前告警』。"；
6) 额外提供一个 demo() 一键跑完整巡检剧情的脚本，方便录屏与 QA。
```

## 3. Skill 来源（本 Demo 用到的技能）

- **素材处理**：ffmpeg 抽帧、`tile` 拼时间线缩略图、`crop` 裁剪放大读小字。
- **视觉自检**：headless Chrome（`--headless=new` + SwiftShader 软件 WebGL）截图 + 控制台错误收集 → 让 AI 看自己的截图迭代。
- **三维**：Three.js r169（InstancedMesh / CanvasTexture / 自发光 + 加色精灵）。
- **图表**：Canvas 2D 手绘（环形仪表、柱状图、折线、环图、sparkline）。
- **语音**：Web Speech API（SpeechRecognition / speechSynthesis）。
- **对话**：本地关键词 + 正则打分意图引擎（可离线复现，不受网络与密钥影响）。
- **工程**：esbuild 打包为单文件 `dist/app.js`（可 `file://` 直接双击），零依赖 Node 静态服务器 `scripts/serve.mjs`。
> 抽帧素材说明：`ref/keyframes/` 保留 40 张关键帧（JPEG，1100px 宽，帧号 = 视频秒数+1）；
> 需要全部 263 帧时执行：`ffmpeg -i ref/douyin_original.mp4 -vf fps=1 ref/frames/f_%04d.png`。
