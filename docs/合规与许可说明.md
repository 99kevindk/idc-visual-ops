## 1. 为什么协议实现没有法律风险

- Modbus、SNMP、MQTT、HTTP、WebSocket 都属**公开标准**：规范文本可自由获取，**实现规范不构成侵权**，也不需要向任何组织缴纳授权费。
- 本项目做的是「**按标准自行编写客户端**」：不链接、不内嵌、不反编译任何厂家的库、SDK、驱动或加密狗组件。
- 唯一需要留意的是**端口与约定俗成**（Modbus 502、MQTT 1883/8883），这些属于行业惯例，非法律限制。
- 协议标准组织对专利的立场：IETF/OASIS 均有免版税（RF）政策；Modbus Organization 的规范公开且无授权费。

## 4. 点表与真实设备对接（唯一需要你注意的"人为风险"）

- 仓库里的 `src/pointtable.js`（39 设备 / 260 测点）是 **demo 数据**：寄存器地址、SNMP OID、MQTT Topic、量程与阈值都是为了让演示能跑通而**编造的规则值**，**不是**任何厂家手册的抄录。
- **接真实设备时请务必注意**：厂家的《通信协议手册》《点表》通常带**保密条款（NDA）**。
  - ❌ 不要把厂家点表原文、手册截图、设备序列号、IP/账号密码提交到公开仓库；
  - ✅ 正确做法：只把**你需要的字段**填进本地 `src/pointtable.js`（或导入 CSV），公开仓库里只保留"示例点表结构"；
  - ✅ 如需把真实点表纳入版本管理，请用**私有仓库**或将配置放在 `*.local`（已在 `.gitignore` 中）。
- 同理：**真实机房拓扑、机柜编号、门禁与视频流地址**都属于敏感信息，公开前请脱敏。

## 5. ⚠️ 语音识别与数据出境（机房场景的重点合规项）

本项目语音输入的实现是浏览器原生 **Web Speech API**：

| 事实 | 影响 |
|---|---|
| Chrome / Edge 的 `webkitSpeechRecognition` 会把麦克风音频**上传到浏览器厂商的云端服务器**做识别 | 机房内的语音内容可能包含**客户名、设备编号、故障信息**等，属于业务数据 |
| 中国境内机房 + 境外厂商云服务 | 可能触发**数据出境**与**个人信息保护法（PIPL）**相关的合规要求 |
| 浏览器其余部分（3D、动环、图纸）均为**纯本地**，不上传任何数据 | 仅语音识别一条链路存在外发 |

**建议（按合规强度递增）**：

1. **演示/内部使用**：保持现状，但明确告知使用者"语音识别由浏览器云端处理"（本项目 UI 已标注"本地演示数据"，建议再加一行提示）；
2. **生产/涉密机房**：
   - 关闭语音识别，改用 `src/xiaowei.js` 的**文字输入**通道（本平台已支持，功能完整）；
   - 或接入**本地化 ASR**（如 whisper.cpp、FunASR、讯飞/百度私有化部署），在 `IDC.xiaowei` 里把 `SpeechRecognition` 替换为本地识别服务 —— 接口已隔离（`listen()/stop()/ask()`），替换成本很低；
   - TTS（`speechSynthesis`）在多数平台为**本地合成**，可保留。
3. 若坚持用浏览器云端 ASR，请做**数据脱敏**（不含客户名、IP、账号）并完成法务/合规评估。
